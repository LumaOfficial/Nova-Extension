Security Policy
Nova AI Browser Extension
Contact: lumasupport@tidio.xyz
Repository: Nova-Extension
Status: Beta
Last updated: October 23, 2026
1. About This Policy
This security policy explains how to report suspected security vulnerabilities
or privacy problems in the Nova AI Browser Extension.
The version available in this GitHub repository is beta software. It may
contain security vulnerabilities, privacy issues, unstable behavior, insecure
dependencies, server problems, or other defects.
Security reports are welcome and may be used to improve the stability and
safety of the Extension. However, submitting a report does not guarantee that
Luma will respond, provide a timeline, release a fix, or continue development.
2. How to Report a Vulnerability
Please report suspected vulnerabilities privately by emailing:
lumasupport@tidio.xyz
Use the subject line:
SECURITY REPORT — Nova AI Extension
When possible, include:

A clear description of the suspected vulnerability
The affected version or commit
The affected browser and operating system
Steps needed to reproduce the issue
The security or privacy impact
Screenshots, logs, or proof-of-concept code
A suggested fix or mitigation, if available
Whether the issue has already been disclosed elsewhere

Please do not include real passwords, authentication codes, private keys,
payment information, health information, or other sensitive personal data in a
report.
3. Do Not Publicly Disclose Details First
Please do not post vulnerability details, exploit code, private data, or
security-test results in a public GitHub issue, pull request, discussion,
social-media post, or other public location before contacting us.
Public disclosure may expose users to unnecessary risk and may make it harder
to investigate or fix the issue.
If you believe there is an active risk to users, clearly mark the report as
urgent.
4. What Happens After a Report
Luma may:

Confirm receipt of the report;
Review and investigate the issue;
Ask for additional information;
Determine whether the issue affects the Extension, a server, a dependency,
a browser, or a third-party service;
Develop or recommend a mitigation;
Release an update or configuration change; and
Publish a security notice when appropriate.

Because the Extension is beta software, response times and remediation
timelines are not guaranteed.
5. Scope
Reports may include issues involving:

Excessive or unexpected browser permissions
Unauthorized access to webpage content
Unexpected transmission of data
Exposure of prompts or user information
Insecure storage
Authentication or authorization failures
Cross-site scripting
Code injection
Malicious or compromised dependencies
Server-side security problems
Insecure update behavior
Privacy or data-retention problems
Remote-code-execution risks
Extension impersonation or supply-chain risks

Third-party services, browsers, operating systems, APIs, websites, and
dependencies may have separate security-reporting procedures. Where an issue
belongs to a third party, Luma may direct you to that provider or coordinate
with the provider where appropriate.
6. Responsible Testing
When testing the Extension, you agree to:

Use only systems, accounts, devices, and data that you are authorized to
test;
Avoid accessing, changing, deleting, or disclosing other people's data;
Avoid disrupting services or degrading availability;
Avoid sending spam, phishing messages, or malicious content;
Avoid testing against real users or production systems without permission;
Stop testing if you discover access to sensitive information; and
Report the issue promptly and privately.

Do not intentionally download, retain, copy, or disclose personal information
or confidential data discovered during testing.
7. Out-of-Scope Reports
The following may not qualify as security vulnerabilities:

Reports based only on missing security headers without demonstrated impact;
Self-XSS requiring the victim to paste code into developer tools;
Spam or content-moderation complaints;
Issues caused entirely by unsupported browsers or modified builds;
Vulnerabilities in third-party services that do not involve Luma-controlled
code or systems;
Reports requiring unlikely or unrealistic user interaction;
General requests for features or improvements;
Automated scanner results without a demonstrated security impact; and
Social-engineering reports involving people who are not authorized to act
on behalf of Luma.

Luma will determine the final scope and severity of a report.
8. Beta Limitations
Because this Extension is in beta:

Security fixes may be delayed or unavailable;
Features may change without notice;
Repository code may not match every distributed build;
Servers and third-party services may change;
Vulnerabilities may remain unresolved;
Releases may be withdrawn or discontinued; and
No security level or response-time guarantee is provided.

Users should avoid relying on the beta for sensitive, regulated, financial,
medical, educational, professional, or security-critical activities.
9. Security Updates
Security updates, release notes, mitigations, or other notices may be
published through this repository or another official Luma communication
channel.
Users are responsible for checking for updates, reviewing changes, and
installing updates when appropriate.
10. Contact
Security reports and privacy concerns should be sent to:
lumasupport@tidio.xyz
Please do not use public GitHub issues for private vulnerability details.
